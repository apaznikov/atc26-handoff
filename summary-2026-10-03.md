# Summary of results, 2-3 Oct 2026

What was measured or decided on 2-3 Oct. Speedups are over upstream TSan measured in the same leg ("direct")
unless marked; `a` = AMD, `f` = Intel. Details and earlier results are in `optimization-results.md`.

## Table 1. Gave a speedup

| idea | what it is | app | speedup |
|---|---|---|---|
| **DynSTC-RT + N1-ST + N1**: single-thread mode in the runtime | While one thread is alive, all checks are skipped, range checks included; otherwise an inlined "already recorded?" test | FFmpeg | `f` **+30.5 %** |
| **FE-INL**: inlined function entry/exit | TSan's per-call bookkeeping runs in the program, not in a runtime call | MySQL | `a` **+9.4 %** (all 8 sysbench scripts gain); `f` −3 % |
| **FE-INL + N1** | plus the inlined fast-path test | Redis | `a` **+7.4 %**, `f` **+5.7 %** |
| **SWMR-ROOTS**: globals written before readers start | No checks on reads if the only write precedes every reader thread | memcached | `a` +0.9 % |
| **EA-CONTENTS**: contents-sensitive escape analysis | A pointer read from a container does not make the container shared | memcached | `a` +1.4 % |

## Table 1a. Gave a speedup, based on annotations

| idea | what it is | app | speedup |
|---|---|---|---|
| **EVCONF**: thread-owned objects under a run-time guard | Checks on objects annotated as owned by one thread are skipped while a guard holds | memcached | `a` **+30.4 %**, `f` ~+22 % |
| **LO-OBJ-G v5**: lock-owned objects under a guard | Checks on objects annotated as protected by their owner's lock are skipped while the lock is held; v7 adds a latch that closes an unlocked page copy | SQLite | `a` **+18.5 %** (both subtests, over the faster stock arm) |

## Table 2. Gave nothing

| idea | what it is | app | result |
|---|---|---|---|
| **Earlier levers on the new workloads** | FE-INL, N1, N1-L, VWIDE-loops, N1-ST, the paper's DynSTC, each on top of the best | memcached, Redis, MySQL | none adds; N1 costs MySQL 10 % |
| **N1-ATOMIC** | inlined test for atomic operations | Redis | `a` +1.6 % over 4 offsets, not resolved |
| **Own-stack skip** | skip checks on the accessing thread's own stack | MySQL | unsound ceiling +5.3 % net; a sound form ≈ −1 %: parked |
| **Whole-program mode, cross-unit parameter facts** | summaries for MySQL; "argument is local in every caller" across units | all | ≤ 0.14 % of checks |
| **InnoDB latch ownership, ODR trust** | lock ownership for MySQL's own latches; trusting C++ inline bodies | MySQL | ≤ 3.2 % / 0.02 % of checks |
| **Thread ids by creation history** | may-happen-in-parallel from abstract thread ids | all | no static form reaches the mass |
| **Runtime code alignment** | 64-byte alignment of the runtime's access paths | FFmpeg, memcached | a trade: FFmpeg +1.3 %, memcached −1 % |

## Table 4. Method and infrastructure findings of 2-3 Oct

| finding | consequence |
|---|---|
| The fork point's stock TSan leaves fields of escaped locals unchecked (an upstream defect fixed in April 2025) | the baseline is upstream with that fix; the bare fork point is not used |
| Our runtime cost 2-3 % on the stock path (extra instructions on the miss and eviction paths) | fixed: the camera-ready runtime executes upstream's instruction count; ±1-2 % from code placement remains, so figures are quoted over upstream in the same leg |
| Client and server sharing CPUs changes the size of effects (memcached, Redis, MySQL) | every server leg runs with server and client on disjoint CPUs |
| MySQL's old Intel loss of 6-12 % came from 36 connections on a 48-CPU set | MySQL runs 24 connections on both machines |
| The SQLite parser read only stress2 | fixed and guarded; re-read results hold on both subtests |
| apollo's disk filled up; x265 escaped the CPU pinning | cleaned and archived; cpuset delegation enabled |
