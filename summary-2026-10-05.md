# Summary of results, 3-5 Oct 2026

What was measured or decided from the afternoon of 3 Oct (after the summary of 2-3 Oct) to 5 Oct 12:10, when all
work was parked. Speedups are over upstream TSan measured in the same leg ("direct"), 4 offsets, unless marked;
`a` = AMD, `f` = Intel. Details and earlier results: `optimization-results.md`; premises: `soundness-fixes.md` §6;
hotspots: `hotspots.md`.

## Table 1. Gave a speedup, based on annotations

| idea | what it is | app | speedup |
|---|---|---|---|
| **EVCONF-RANGES** | the event-loop confinement guard extended to memset/memcpy on an owned object; one memset zeroing each response object was 16.6 % of the cycles | memcached | on top of the 3 Oct configuration: `a` **+18.5 %**, `f` **+13.9 %** (equal to the unsound ceiling) |
| **EVCONF-ARGS** | the confinement carried into the hash function's key argument: a clone of MurmurHash3 with the key reads unchecked while the guard holds | memcached | on top: `a` **+7.3 %**, `f` **+7.2 %** |
| **EVCONF-INTERCEPT** | the guard around memchr, strlen and the request-key side of bcmp on the confined read buffer | memcached | on top: `a` **+7.5 %**, `f` **+5.7 %** |
| **memcached, all of the above together** | EVCONF + SWMR-ROOTS + EA-CONTENTS + RANGES + ARGS + INTERCEPT, with IN-BOUNDS | memcached | `a` **+80.3 %**, `f` **+58.5 %** (the 3 Oct configuration: +31.1 % / +23.3 % in the same legs) |
| **Quiet threads** (QUIET-THREADS, REDIS-MAIN: silent-thread mode, the Redis phase guard) | Redis's main thread skips its checks, range checks included, while every other thread is quiet since a release it acquired; annotations register the threads' park objects and attest their start | Redis | `a` **+38.7 %**, `f` **+31.4 %** (+26.3 % / +25.6 % over FE-INL + N1 in the same legs) |

All five passed independent audits (A43-A58b) before their numbers were quoted, and race preservation against stock
(10 runs per arm): memcached loses no race; the quiet mode loses no seeded race.
